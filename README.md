Практика 6: Сервис подписок
📖
Теория + практика
Финальная практика модуля — сервис подписок. Здесь сходится почти весь модуль: тарифы и ограничения, Scheduler с 
распределённой блокировкой, межсервисный вызов через OpenFeign, прокидывание логина через фильтр API Gateway и кеширование в 
Redis с инвалидацией через Kafka.

📋 Задача
Создайте новый сервис, который хранит пользователя и его подписку.

Подписка содержит: логин пользователя, тип подписки (бесплатная или платная), дату истечения срока подписки.
Первичный ключ пользователя — его логин в Keycloak.
⚠️ Пользователя заводим вручную
Регистрация через Keycloak (чтобы пользователь автоматически попадал в сервис подписки) у нас не реализована. Поэтому 
пользователя и его подписку добавляйте в таблицу вручную — например, через SQL-вставку. Логин при этом должен совпадать с 
логином пользователя в Keycloak.

Ограничение по размеру файла
Платная подписка и срок не истёк → пользователь может загружать файлы более 100 МБ.
Бесплатная подписка → файлы не более 100 МБ.
Scheduler
Добавьте в сервис Scheduler, который проверяет, не истекла ли подписка. Если срок истёк — заменяет платную подписку на 
бесплатную.

Интеграция с FlowManager
Перед отправкой задачи в сервис конвертации FlowManager должен проверить, не истекла ли подписка. Если она истекла и 
размер файла более 100 МБ — вернуть пользователю ошибку и не отправлять задачу на выполнение.
Для REST-запроса из FlowManager в сервис подписки используйте библиотеку OpenFeign.
Логин пользователя через API Gateway
Добавьте в API Gateway новый фильтр, который достаёт из JWT-токена Keycloak login и кладёт его в заголовок запроса X-User-Login. 
Благодаря этому любой сервис за гейтвеем всегда сможет получить логин пользователя из заголовка.

Кеширование в Redis
Добавьте кеширование информации о подписке через NoSQL-базу Redis.
Redis находится на стороне FlowManager — потому что кеш нужен именно ему: чтобы при каждой загрузке файла не ходить лишний 
раз по REST в сервис подписки за статусом подписки, FlowManager берёт её из своего кеша.
При инвалидации кеша (когда Scheduler меняет платную подписку на бесплатную) запись нужно удалить и из кеша Redis: отправьте 
событие по Kafka в сервис, где используется кеш, чтобы тот очистил соответствующую запись.
